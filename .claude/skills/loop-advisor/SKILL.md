# ループ提案（loop-advisor）

エージェントに1回作業させた後、**それをループにすべきか**を判断し、必要なら
ストック済みのループから提案する。判定を飛ばして提案しない。

> 前提: ループ化は万能ではない。判断が要らない定型作業は cron や CI で十分であり、
> 合否を機械判定できない作業をループに載せると「速度だけ上がってミスが再生産される」。

---

## 手順

### STEP 1. そもそもループにすべきか判定する（省略しない）

次の3点を**すべて**満たすときだけループ化を勧める。1つでも欠ければ「ループ化しない」と答える。

| 判定軸 | 満たす例 | 満たさない例 |
|---|---|---|
| 自動で検証できる | テストが通る / エラー率0.1%未満 / 表示1.5秒以内 | 「いい感じの文章か」 |
| 失敗しても戻せる | ブランチ上の修正、下書き生成 | 本番DBの破壊的変更、対外送信 |
| 停止条件を数値で書ける | 5回試して未達なら停止 | 「納得いくまで」 |

さらに**反復性**を確認する。一度きりの作業はループ化のコストを回収できない。

判定は次の形で短く伝える。

```
ループ化: 推奨 / 条件付き / 非推奨
理由: （3軸のどれを満たし、どれを満たさないか）
```

**非推奨の場合はここで終える。** 代わりに「人が対話しながら進める」「cron/CIで足りる」
のどちらかを示す。無理にループを提案しない。

### STEP 2. ストックから候補を探す

`search_loops.py` で検索する。**インデックス（loops_index.jsonl）を直接開かない**
（1,354行ありコンテキストを浪費する）。

```bash
python .claude/skills/loop-advisor/search_loops.py "CI 失敗 修正" --top 5 --detail
```

| オプション | 用途 |
|---|---|
| `--type turn\|goal\|time\|proactive` | ループタイプで絞る |
| `--src DI\|FF\|EL\|LE\|ALH\|ALE\|AW` | 出典で絞る |
| `--top N` | 件数（既定5） |
| `--detail` | 使うタイミング・完了条件も表示 |

検索語は**作業の対象と動作**で組む（例: `CI 失敗`、`ドキュメント 同期`、`依存 更新`）。
0件なら語を減らす。

### STEP 3. ループタイプを決める

| タイプ | 起動 | 停止 | 向く作業 |
|---|---|---|---|
| **ターン型** | 人のプロンプト | 完了とエージェントが判断 | 短い単発、探索 |
| **ゴール型** | 人のプロンプト | 条件達成 or 回数上限 | 完了条件が検証可能 |
| **時間型** | 時間間隔 | 人が止める / 作業完了 | 反復作業、外部監視 |
| **能動型** | イベント・スケジュール（無人） | 各タスクは目標達成で終了 | 定常的に発生する流れ |

### STEP 4. 停止条件を設計する（必須・多重に塞ぐ）

**1種類では防げない。** 次を組み合わせて提案する。空欄で出さない。

```
① 成功   : <機械判定できる完了条件>
② 回数   : <N>回試して未達なら打ち切る
③ 予算   : <金額 or 時間>（サブエージェントの消費も合算）
④ 無進展 : 直近<N>回で成果物に変化がなければ打ち切る
⑤ 異常   : <連続失敗・同一エラー反復・範囲外ファイル変更 など>
戻し先   : <誰に何を渡すか。無いと詰まったまま消費し続ける>
```

**人間の承認を挟む操作**（自動実行させない）:
main へのマージ / 本番反映 / 外部送信 / ファイル・ブランチ削除 / 依存追加

### STEP 5. 任せる範囲を段階で勧める

いきなり無人で回さない。

1. **報告のみ** — 調査・検出して報告するだけ。変更しない
2. **検証付きの修正案** — 証拠を添えて提案。承認と反映は人間
3. **自動反映** — 検証通過分は自動。例外時のみ人間

初回は必ず **1. 報告のみ** から勧める。

## 出力の形

```
【ループ化の判定】推奨 / 条件付き / 非推奨
  理由: …

【提案するループ】
  1) <タイトル>（出典: <src> / <id>）
     なぜ合うか: …
  2) …

【ループタイプ】<タイプ>（理由: …）

【停止条件】
  ① 成功 … ② 回数 … ③ 予算 … ④ 無進展 … ⑤ 異常 …
  戻し先: …

【始め方】段階1（報告のみ）から。次の条件を満たしたら段階2へ: …
```

ストックに合うものが無ければ、**無理に当てはめず**「新規設計」と述べ、
STEP 3〜5 の枠組みだけを示す。

---

## やってはいけないこと

- STEP 1 の判定を飛ばして提案に入る
- 停止条件のどれかを空欄のまま出す（特に予算と戻し先）
- エージェントの「できました」を根拠に完了とする（自己申告は証拠にならない。
  テスト・CIなど外部の証跡で判定する）
- `loops_index.jsonl` を直接読み込む（必ず `search_loops.py` を使う）
